# 方法论包规范

一个方法论包 = 一个文件夹（或打成 zip），决定这台引擎「按什么标准判」。

## 三种导入方式，怎么选

| 方式 | 适合 | 会改变结论吗 |
|---|---|---|
| **界面粘贴原文**（推荐） | 刚学完一门课 / 一篇帖子，手里只有文字笔记 | 会。AI 把原文里的数字落成阈值、把倾向落成权重，你核对后保存 |
| **pack.yaml** | 要精确控制每个阈值；要分发给别人用 | 会。逐项生效，写错的键会在详情页黄色提示 |
| **只有 SKILL.md** | 只想让 AI 按某种视角写解读 | 不会。只影响报告解读文字 |

界面粘贴原文保存后，会在 `method_packs/user/<id>/` 生成 `pack.yaml`（判定标准）和 `SKILL.md`（原文，供解读引用）。想分发给别人，把这个文件夹打成 zip 发出去即可。

> 为什么不做成 MCP：MCP 适合「提供数据」，方法论是「判定标准」。做成 MCP 要额外起一个进程、写代码，用户还得配置；而文件夹 / zip 拖进来就能用，也不会执行任何代码，更安全。数据源用 MCP 接，方法论用方法论包装，两者分工。

## pack.yaml 字段

所有字段都可选，建议至少写 `id` 和 `name`。

```yaml
id: my-jingpu                 # 英文小写和连字符；同 id 再导入需勾选「覆盖」
name: 我的精铺三板斧
version: "1.0"
author: "自己整理"
description: 一句话说明这套打法
tags: [精铺, 利润优先]
type: declarative             # declarative（默认）| skill | mcp

weights:                      # 五维权重，会自动归一化
  market_capacity: 0.20       # 市场容量
  competition: 0.25           # 竞争
  trend: 0.10                 # 趋势
  differentiation: 0.20       # 差异化
  margin_barrier: 0.25        # 利润与供应链

thresholds:                   # 只能用下表里的组名和键名；注意每个键的单位（见下表）
  demand:      {min_weekly_search_volume: 3000, warn_weekly_search_volume: 1500}
  competition: {top3_click_share_pass_max: 0.35, top3_click_share_warn_max: 0.5, top3_click_share_fatal: 0.6,
                median_reviews_pass_max: 800, median_reviews_warn_max: 3000}
  price:       {avg_price_pass_min: 20, avg_price_warn_min: 15, avg_price_warn_max: 45}
  margin:      {gross_margin_pass_min: 35, gross_margin_warn_min: 25, gross_margin_fatal_below: 25}   # 百分数
  supply:      {offers_pass_min: 10, moq_pass_max: 500}

rules:
  disabled: []                # 只有方法论明确说「不看某项」才关；没提到 ≠ 不要

defaults:                     # 新建选品时的默认开关
  check_ip: true
  check_voc: true

lens: |                       # AI 解读视角（不改结论）：什么算机会、什么算否决、该盯哪些数字
  按这套打法，……
```

## 可用的阈值组与键

**单位最容易写错**：毛利率、需求趋势、评论区间难度用**百分数**（35 = 35%）；集中度、各种占比用**小数**（0.35 = 35%）。写反了引擎会自动换算并在详情页提示，但请改正源文件。

| 组 | 键 | 单位 | 含义 |
|---|---|---|---|
| demand | min_weekly_search_volume / warn_weekly_search_volume | 次/周 | 核心词周搜索量的通过线 / 警戒线 |
| trend | growing_pct / warn_decline_pct | 百分数 | 需求同比增长线 / 下滑警戒线（-10 = 下滑 10%） |
| competition | top3_click_share_pass_max / _warn_max / _fatal | 小数 | Top3 点击集中度通过 / 警戒 / 一票否决线 |
| competition | listing_count_pass_max / _warn_max | 个 | 在售链接数 |
| competition | median_reviews_pass_max / _warn_max | 条 | 头部评论中位数 |
| competition | young_listing_share_pass_min / _warn_min | 小数 | 头部一年内新链接占比 |
| competition | review_band_pass_min / _warn_min | 百分数 | 评论区间难度 |
| price | avg_price_pass_min / avg_price_warn_min / avg_price_warn_max | 美元 | 售价带 |
| ad | natural_share_pass_min / _warn_min | 小数 | 头部自然流量占比 |
| supply | offers_pass_min / offers_warn_min / moq_pass_max / moq_warn_max | 条 / 件 | 1688 供应商数与起订量 |
| margin | gross_margin_pass_min / _warn_min / _fatal_below | 百分数 | 毛利率；低于 fatal 一票否决 |
| margin | ceiling_headroom_pass_min / _warn_min | 倍 | 采购价上限 ÷ 实际采购价 |
| unit | landed_ratio_pass_max / _warn_max、fba_ratio_pass_max / _warn_max | 小数 | 采购+头程、FBA 占售价 |
| verdict | do_min / conditional_min / defer_min | 分（0–100） | 做 / 有条件做 / 暂缓 的分数线 |
| verdict | coverage_min / coverage_fatal_min | 小数 | 数据覆盖下限 |

完整列表以界面「方法论库 → 详情 → 规则」为准（它直接读引擎）。

## 安全

- 导入只解析 `.yaml .yml .md .json .txt .csv` 和图片；脚本、可执行文件会被丢弃，永远不会运行。
- zip 拒绝绝对路径、`..` 和符号链接，单包上限 20MB、400 个文件。
- 不要把任何 API Key 放进方法论包。
